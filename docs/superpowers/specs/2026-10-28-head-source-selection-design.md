# 头像来源选择

## 用户目标

从视频和每张照片分别重建三维头像。用户查看候选后选择一个头像。后续人物构建和交互使用该头像。

## 已确定的方式

用户选择“每张照片各生成一个候选，与视频头像一起选择”。视频自动选择一个清晰正脸。身体主照片和每张补充照片分别检查，重复文件只处理一次。

候选使用现有 GAGAvatar 模型重建。显示原始参考、正面和左右侧面渲染预览。预览必须来自保存的三维高斯参数。仅裁剪照片不算完成重建。

另一种方式是视频、照片各生成一个候选。该方式减少处理次数，但不能比较不同照片。用户未选择此方式。不新增模型或云服务。

## 操作流程

1. 导入素材，点击“生成头像候选”。
2. 解析视频和照片，逐个重建头像并保存预览。
3. 用户选择一个已完成的候选，点击“使用此头像”。
4. 点击“构建人物”。构建身体，将选中的头像绑定到身体，检查加载、表情和声音。
5. 人物包通过检查后，点击“启动交互”。

照片未检测到唯一清晰人脸时，显示原因并禁用该候选。单个候选失败不能隐藏其他成功候选。没有成功候选时，禁止后续构建。视频和照片的面部特征不再混合校准。身体服装仍来自身体主照片，声音仍来自视频。

## 保存与切换

- 每个人物保存候选清单、来源文件、实际视频时间、源文件校验值、模型版本、三维参数和预览。
- 保存所选候选编号。重启服务后恢复选择。
- 候选三维参数独立于身体保存。选定后，再生成与身体状态绑定的 `head.json`。复用现有头部加载器和渲染器。
- 重新生成采用新版本目录。写入完成后再替换清单。失败时保留旧清单和已生效的人物包。
- 切换选择后，人物需要重新执行构建和检查。可复用相同素材和权重的身体。不能继续加载旧头像冒充新选择。
- 构建、候选生成、加载或交互期间禁止修改选择。所有显卡任务使用现有进程锁。

## 兼容与边界

保留现有接口。新增候选生成、列表和选择接口。新导入人物要求先选择头像。现有人物保持可用；用户生成候选并改选后，进入新流程。保留命令行头部构建入口，移除固定第4秒来源的依赖。

本次不增加多人身份匹配。存在多个相近大小的人脸时，显示无法自动确定的原因。背面和遮挡区域仍由模型估计。侧面预览用于检查重建，不表示相似度已通过人工验收。

## 检查

测试覆盖来源分离、缺少人脸、单项失败、校验失败、选择持久化、忙碌保护、改选失效和旧人物兼容。运行完整后端测试及前端编译。用本机素材实际生成视频和照片头像，选择并重新加载其中一个，检查身体与声音来源未被替换。
