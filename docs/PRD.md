# 照片数字人 · 产品需求文档（PRD）

| 项目 | 内容 |
|---|---|
| 产品名 | 本机照片数字人（Local Photo Digital Human） |

| 状态 | 可用（流式音画链路待验收） |
| 日期 | 2026-11-07 |
| 关联文档 | [代码设计](architecture.md) · [技术讲解](technical-guide.md) |

## 1. 背景与问题

现有数字人产品大多把推理放在云端：按分钟计费、素材要上传、音色与形象不可控、弱网下音画不同步。而在本地把一个"能对话的数字人"跑起来，门槛又集中在三件事上：

1. **形象资产重**：传统方案要训练说话人模型，普通人拿不到、也等不起。
2. **链路长**：对话模型、语音合成、口型驱动、传输四段各自为政，首句延迟被逐段累加。
3. **显存冲突**：声音和画面两个模型抢同一块显卡，冷启动、换入换出、并发都会让第一句话变慢。

本项目要验证的命题是：**只用一张照片和一段几秒的人声（默认取 8 秒），能否在本机做到"问一句、几秒内开口"的可对话数字人，并且素材与对话完全不出网。**

## 2. 目标用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 个人创作者 | 给自己的短视频/直播做一个出镜替身 | 成本低、上手快、形象像本人 |
| 展厅/前台 | 一块屏幕 + 一台带显卡的机器做接待讲解 | 稳定连续运行、声音自然、能打断 |
| 产品/算法团队 | 验证数字人交互形态，做内部 Demo | 可改模型、可量延迟、可复现 |

不作为目标用户：需要 7×24 大规模并发的商业客服、需要多路同时出镜的直播中台。

## 3. 产品目标与非目标

### 3.1 目标

- **像**：照片原比例呈现，口型与表情跟随语音，25 fps 不掉帧。
- **快**：热启动下首句声音 ≤ 8 s、首段音画进入播放队列 ≤ 12 s；回答过程中文字与语音逐句推进，不等整段生成。
- **稳**：连续对话 30 分钟无累积失步、无文件泄漏；打断后 1 s 内回到可对话状态。
- **私**：推理、素材、日志全部本机；运行期不联网。
- **可控**：音色、情感、语速、画面清晰度、延迟与画质的取舍都有配置项，不藏魔法。

### 3.2 非目标

- 多人并发、多会话复用同一张卡（当前明确为单会话）。
- 视频生视频、全身动作、手势。
- 手机端/移动浏览器适配（按桌面 Chrome/Edge 设计）。
- 自动确认声音授权：必须人工试听后确认。

## 4. 端到端用户旅程

```
导入素材 ──► 准备人物 ──► 试听并确认声音 ──► 开始对话 ──► 多轮问答/打断 ──► 断开
   │            │                │                │              │
   │            └ 失败可重试      └ 未确认则阻塞    └ 建 WebRTC    └ 会话空闲 15 分钟自动回收
   └ 校验格式/大小/哈希
```

关键体验约束：

- 准备过程中禁止开新会话、换素材、删人物，避免"边准备边用"产生半成品。
- 未确认声音时，`/sessions` 直接拒绝，错误文案是"请先准备照片并确认声音"。
- 会话中断线、刷新页面、关闭标签页都要能回收显存与临时文件。

## 5. 功能需求

优先级：P0 = 没有就不能用；P1 = 影响体验；P2 = 增强。

### FR-1 素材导入（P0）

- 支持 jpg/jpeg/png 照片与 mp4/mov/mkv/webm 视频；单文件 ≤ 1 GiB，文件名不得含路径分隔符或以 `.` 开头。
- 导入时复制为不可变副本并记录 SHA-256；后续所有校验以哈希为准，不信任文件名。
- 视频只取音轨，画面不进入链路；音轨需 ≥ 6 s 清晰语音，≤ 10 分钟。
- 验收：换素材后旧校验自动失效，人物回到 `imported`，必须重新准备。

### FR-2 人物准备（P0）

一次准备任务依次完成：

1. 校验素材哈希。
2. 从音轨中自动挑选 6 s 参考片段（优先语音占比高、无爆音、响度接近 -20 dBFS 的窗口）。
3. 提取照片特征（人脸检测、关键点、外观特征、相机矩阵），生成 4 s 待机视频。
4. 若声音未确认，停在 `voice_pending` 等人工试听。
5. 确认后合成一句固定试听音，写 `voice/sample.wav`，人物置为 `ready`。

要求：

- 照片缓存按"照片哈希 + 模型版本 + 源码提交 + 最大边长"做键，命中则复用，避免重复计算。
- 任务进度可轮询（`stage` / `progress` / `status`），失败要给出可读原因。
- 服务重启时，处于 `queued/running` 的任务标记为失败并提示重新准备，不假装还在跑。
- 验收：同一人物重复准备，第二次跳过照片推理；换照片后缓存必然失效。

### FR-3 声音确认（P0）

- 参考音频必须能试听，确认动作单独落库（`voice.confirmed`）。
- 确认状态与参考音频哈希绑定：参考音频变了，确认自动失效。
- 不提供"跳过确认"的快捷入口。
- 验收：未确认时 `/tts` 返回 409「请先试听并确认参考声音」。

### FR-4 会话建立（P0）

- `POST /api/sessions` 返回 `session_id`、画面宽高、25 fps。
- 同一进程同时只允许一个会话；准备/导入/删除期间拒绝建会话（409）。
- WebRTC 只收不发视频，麦克风按需上行；连接 30 s 未建立要提示超时。
- 空闲 900 s 自动回收；`DELETE` 立即回收。
- 验收：关闭浏览器后，端口上的帧发送在数秒内停止，显存与临时目录被释放。

### FR-5 文本对话（P0）

- 输入 ≤ 500 字，Enter 发送、Shift+Enter 换行，输入法组合态不误发。
- 生成中禁止重复提交；可随时打断。
- 回答限制"最多两句"、≤ 300 字，避免单轮过长拖垮延迟。
- 回答必须带情感标签，且只允许 `neutral/happy/sad/angry`。
- 验收：模型返回非法 JSON 时给出"回答格式无效"，不把原始 JSON 念出来。

### FR-6 语音对话（P1）

- 按住说话，最长 30 s，松手后自动识别并回答。
- 麦克风未授权时降级为纯文字，不阻塞会话。
- 识别为空或过短（< 0.2 s）时提示"未检测到语音"，不进入合成。
- 验收：录音超 30 s 主动停止并提示松开按钮。

### FR-7 情感表达（P1）

- 同一情感同时驱动语音指令与表情索引，不允许"声音开心、脸中性"。
- 情感由对话模型按语义选择，优先克制，不照抄用户情绪。
- 验收：四种情感的语音指令与表情索引一一对应，非法值回落 `neutral`。

### FR-8 打断（P0）

- 打断后立即停止当前轮的生成、合成与播放；队列清空；画面回到待机。
- 被打断轮次的迟到结果必须丢弃，不能覆盖新一轮的文字或计时。
- 验收：连续快速打断 10 次后，仍能正常完成一轮问答，且没有残留临时文件。

### FR-9 逐句流式回答（P1）

- 对话模型按 SSE 返回，收到第一个完整句子就开始合成，不等整段。
- 首句允许在 14 字内遇到逗号时提前切出（可配置），切分不改变原文字词与顺序。
- 前端逐句显示回答文字，最终以完整 `transcript` 覆盖，不出现重复气泡。
- 关闭开关（`dialogue_streaming: false`）时退回整段生成，行为一致。
- 验收：首段进入队列的时间早于整段生成完成的时间；文字拼接与整段一致，无丢字。

### FR-10 播放与音画同步（P0）

- 画面 25 fps，尺寸等于照片原比例，不做裁剪拉伸。
- 声音以 48 kHz 单声道播放；画面按"已消费的 PCM 位置"选帧，而不是按墙上时间。
- 目标音画偏差：P95 ≤ 150 ms；解码端不允许重复 RTP 时间戳。
- 画面供不上时宁可重复上一帧/短暂停顿，也不跳帧错位。
- 验收：`diagnostics=1` 页面能读出采样数、最大偏差、P95、解码帧与丢帧原因。

### FR-11 诊断与度量（P1）

每轮记录并在 `/metrics` 暴露：

| 指标 | 含义 |
|---|---|
| `llm_first_ms` / `llm_first_sentence_ms` | 回答首字 / 首句文字到达 |
| `tts_first_ms` / `tts_first_chunk_ms` | 首句声音完成 / 首个声音块 |
| `portrait_first_ms` / `portrait_first_chunk_ms` | 首句画面完成 / 首个画面块 |
| `first_pair_ready_ms` | 首对音画就绪 |
| `first_enqueue_ms` | 首段进入播放队列（用户可感知的"开口"） |
| `playback_start_ms` | 时间线真正开始出声 |
| `total_ms` / `status` | 整轮耗时与结果（completed/interrupted/failed） |

另需暴露 `delivery_mode`、`stream_underruns`、`stream_buffer_ms`、`paired_buffer_seconds`、`video_frames_dropped`、`video_drop_reasons`、`stream_cleanup_errors`。

### FR-12 人物与素材管理（P1）

- 支持替换照片/视频、删除人物；删除只删项目内副本，保留原始文件。
- 删除前二次确认；删除正在使用的目录要拒绝（路径越界/符号链接保护）。
- 验收：删除后列表、默认人物标记、磁盘目录三者一致。

### FR-13 资源保护与降级（P0）

- 流式生成前检查磁盘余量（默认保留 10 GiB），不足直接拒绝而不是写坏文件。
- 双模型并行要求显存余量 ≥ 1 GiB；不足时自动切串行，并在界面提示"显存余量不足，正在使用串行方式重新准备声音和画面"。
- 串行重试仅允许在"本轮还没有任何一句开始播放"时进行，避免用户听到一半重来。
- 验收：人为压满显存后发起对话，要么串行完成，要么给出明确错误，不允许崩溃或黑屏。

### FR-14 个性化呈现（P1）

- 语气：自然 / 亲切 / 专业 / 活泼，写入对话提示词；当取值为非"自然"且 `runtime.tone_voice` 开启时，同时写入平语句的声音指令。
- 表情：自然 / 微笑 / 严肃 / 惊讶，只在平语句生效；回答带情绪时以对话情绪为准，预设完全忽略。
- 造型：每个人物 1–8 套，各自一份画面缓存，一键切换；切换要求该套已准备且当前无会话。
- 换装：界面只暴露「按图换装」（上传服装图片 + 选填描述 + 开始换装）；预设换色与预设款式保留在 API，不在界面显示。不改渲染参数，而是在准备前改源照片——先在原图上分出发型与上装，再做换色或换款式，产出一张同人新图作为新造型。脸、颈部与背景必须逐像素不变（掩膜外）。
  - 换色：8 个预设色，Lab 空间替换色度、保留亮度纹理；单张约 8 秒，不需要额外模型。
  - 换款式：6 个款式预设（衬衫/针织/西装/卫衣/大衣/连衣裙），本地 SD1.5 修补模型重绘掩膜区域，先用底色预填破除深色偏置；768 长边、36 步，约 30 秒。模型未安装时接口返回 503，界面显示"未装模型"。
  - 按图换装：用户上传一张衣服图片，IP-Adapter 把参考图的颜色/材质/大致款式注入掩膜区域；可附一句中文描述，先由本地对话模型译成英文名词短语再进提示词。约 40 秒。参考模型未安装时接口 503。
- 验收：
  - `PUT /settings` 只传一个字段时另一个保持不变；非法字段或取值返回 400 且不落盘；
  - 会话内 `settings` 消息在下一句生效，非法值回 `error` 且清单不变；
  - 未准备的造型不能设为使用中（409）；使用中的造型不能删除；最后一套不能删除；
  - 换装接口：非法 `mode` 400；照片哈希与清单不符 400；生成模型缺失 503；有会话或准备任务时 409；
  - 按图换装：衣服图只作为参考，不落进人物目录；结果同样只新增一套造型；
  - 换装结果必须新增一套造型，不得改动使用中的造型与 `status`；
  - 准备第二套造型不得让已就绪的人物失效，`require_photo_ready` 只校验使用中的那套；
  - 切换造型后会话宽高、画面缓存目录、待机视频都来自新造型。
- 明确不做：渲染期换装（渲染器只重绘头部裁剪区）、按句变化表情。换装只在准备阶段改照片，不进入实时链路。

### FR-15 照片编辑工作台（P1）

编辑台占用中栏主画面区，未连接会话时可用。左栏「编辑照片」进入，「返回对话视图」退出。工作台提供两件事：把照片扩展成全身照，以及按图换装。两者都只新增一套造型，不改使用中的造型与 `status`。

**输入与校验**

- 人物照片、服装图在进入任何模型之前必须校验：真实像素格式（不看扩展名）、像素上限 40 MP、边长与长短边下限、长宽比合理性。
- 人物照片：JPG/PNG，短边 ≥ 320，长边 ≤ 8192，长宽比 0.33–3.0。
- 服装图：JPG/PNG/WEBP，短边 ≥ 256，长边 ≤ 4096，长宽比 0.5–2.0。
- 校验失败必须给出指明具体限制的中文原因，不得只说"格式不支持"。
- 校验只读，不改写源文件，保证 SHA-256 可复核。

**扩图（全身照）**

- 画幅：3:4（默认）与 9:16。目标纵横比超过 1.55 时拆成两段生成，第二段对中间结果重新分割。
- 头部与上半身保持原像素；人脸区差异像素占比必须为 0，否则中止且不产出造型。
- 人物已接近全身时返回 `already_full_body`，不生成、不新增造型，界面给出说明。
- 生成结果按 `quality`（good / fair / low）标注。`low` 时给出"建议换一张照片或重试"的提示，但仍允许保存为新造型。
- 明确不做：姿态骨架控制、换脸、背景替换、多人照片。

**提示词**

- 动作、语气、表情各一个自由文本输入，上限 40 字，中文可。
- 语气同时作用于两条链路：写入画面提示词（神态与身体语言），并写入对话系统提示词与语音指令。表情预设与真实情绪优先于自由文本。
- 自由文本语气上限 60 字，与预设并存；预设的硬规则不能被自由文本覆盖。
- 翻译失败不得阻塞生成，界面提示"未翻译（质量可能下降）"。

**预览**

- 参数改动后 300 ms 内出构图预览（画布、掩膜范围、人物位置），不调用扩散模型。
- 生成过程中每 4 步推送一张中间图，前端按版本号轮询，版本不符返回 409 而不是返回旧图。
- 中间图只保留最近 2 张，文件名带步号，写入用"临时文件 + 原子替换"。

**触发与互斥**

- 生成只能由显式按钮触发：「生成全身照」「按图换装」。不提供拖拽即触发、双击即触发。
- 按钮不可用时必须给出成句原因（分析未完成 / 有准备任务或会话 / 已接近全身 / 模型缺失 / 未选服装图 / 正在生成）。
- 编辑进行中，开新会话、换素材、换造型、删人物一律返回 409，文案含"编辑任务"。

**验收**

- 扩图结果中，掩膜外像素与源照片逐字节相同；`face_diff_ratio == 0`。
- 同一照片的构图预览命中缓存时不重复计算；换照片后缓存必然失效。
- 9:16 请求实际执行两段，报告里 `passes == 2`。
- 服装图校验失败返回 400 且文案指出限制；像素超限返回 413。
- 编辑任务完成时，`result.variant_id` 存在，造型数 +1，`active_variant` 不变。
- 中间图版本不符时 `/jobs/{id}/preview?v=N` 返回 409；任务尚未产出时返回 404。

## 6. 非功能需求

### 6.1 延迟

| 指标 | 目标（热启动） | 现状（本机，2026-11-07） |
|---|---|---|
| 回答首字 | ≤ 1.5 s | 1.3–1.5 s（CPU 3B） |
| 首句文字 | ≤ 2 s | 1.3–1.8 s |
| 首句声音 | ≤ 8 s | 6.6 s（整句模式） |
| 首段音画入队 | ≤ 12 s | 34.3 s（整句模式，画面是瓶颈） |
| 稳态生成速度 | ≥ 1.0× 实时 | 约 0.22× 实时（4.6 倍慢于实时） |

结论：**对话与语音已接近目标，画面渲染是唯一未达标环节**；流式链路已实现但尚未通过验收，默认关闭。

### 6.2 画质

- 输出长边 ≤ 1024，等比缩放；不做美颜、不换脸。
- 说话画面用无损 RGB 中间编码（`libx264rgb`，crf 0），传输用 VP8，按尺寸给 4/6/8 Mbps。
- 不允许为了帧率裁剪人脸区域；掉帧只能来自传输拥塞，不能来自生成端丢帧。
- 个性化不得破坏上述不变量：表情只改条件参数，帧数、25 fps、背景像素与编码参数与默认路径一致；造型切换只换照片与缓存，不允许为对齐码率档位而缩放照片。
- 可量化验收：掩膜外背景逐像素相等；四种表情帧数一致；表情与"自然"的人脸区平均差落在 (1/255, 25/255)，本机实测 6.0–9.6/255、变化像素 8.4–17.7%、掩膜外一致；造型切换后会话宽高与缓存目录同步更新。
- 跨设备一致性只承诺"缓存身份 + 结构不变量 + 已标定预设"：动作扩散、TTS 采样与对话温度均无固定种子，像素级一致不成立；`portrait_seed` 仅供同机诊断。

### 6.3 稳定性

- 连续对话 30 分钟：帧率窗口 ≥ 15 fps、无未解释断流、无临时文件增长。
- 单轮失败不能污染下一轮：generation 失效机制保证迟到结果被丢弃。
- 任一 worker 崩溃，studio 必须能报错并允许重连，而不是整个进程挂死。

### 6.4 隐私与合规

- 运行期离线；模型下载与依赖安装只在 `setup` 阶段联网。
- 素材、参考音频、生成结果都留在 `data/`；删除人物即删除副本。
- 声音克隆必须由使用者确认授权；产品不提供"导入即用"的绕过路径。
- 日志不记录回答正文与音频内容，只记录阶段耗时与错误。

### 6.5 可维护性

- 模型版本、源码提交、文件哈希全部锁定在 `configs/photo-models.json`，启动前校验。
- 任何缓存都带身份（照片哈希 + 模型版本），不允许"看起来一样就用"。
- 关键路径有测试：切句、时间线、分块校验、租约、并发回退。

## 7. 状态与错误语义

人物状态：

```
imported ──build──► preparing ──► voice_pending ──confirm──► preparing ──► ready
   ▲                    │                │                                  │
   └────换素材───────────┴────失败────────┴──────────────► failed ◄────────┘
```

任务状态：`queued → running → (waiting) → complete | failed`。

错误码约定：

| 场景 | HTTP | 文案要点 |
|---|---|---|
| 未准备/未确认声音 | 409 | 请先准备照片并确认声音 |
| 正在准备或有会话 | 409 | 请先停止准备任务或交互会话 |
| 素材格式/大小不合法 | 400 / 413 | 指出具体限制 |
| 人物/会话不存在 | 404 | 不泄露路径 |
| 显存不足（流式） | 409 + `code=stream_memory` | 触发串行回退 |
| 打断 | 409 | 当前回答已停止 |

## 8. 验收标准

发布前必须全部满足：

1. **首响**：热启动下首段音画入队时间中位数比基线下降，且 P95 不退化。
2. **连续运行**：30 分钟 soak，帧率窗口 ≥ 15 fps，无断流、无未清理临时文件。
3. **打断**：连续打断 10 次后仍可完成一轮，旧轮次文字/计时不串台。
4. **音画同步**：浏览器实测 P95 ≤ 150 ms（`diagnostics=1`）。
5. **清理**：会话关闭后 `data/sessions/<id>` 与系统临时目录无残留。
6. **降级**：显存压满时能串行完成或明确报错，不崩溃。

当前状态：1（流式未验收）、2（未跑 30 分钟）、3（待复测）、4（未在流式模式测量）、5（未跑清理检查）尚未全部通过，因此 `photo_streaming` 保持 `false`。

## 10. 风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| 画面渲染 4.6× 慢于实时 | 首段入队 30 s+，无法"实时对话" | 降步数/批/步长已用上；下一步换解码后端或更轻模型 |
| 单卡双模型抢显存 | 并行时 OOM 或换入换出抖动 | 1 GiB 余量准入 + 串行回退 + 预热后权重回 CPU |
| WSL2 文件锁与进程身份差异 | 开发机通过、Windows 直跑失败 | 关键路径用 `/proc`、`flock`，测试在 WSL 内跑 |
| 声音克隆授权 | 法律与伦理风险 | 强制试听确认，记录参考音频哈希 |
| 对话模型能力有限（3B/CPU） | 回答短、偶发格式错误 | 结构化输出 + 解析兜底 + "最多两句"约束 |
